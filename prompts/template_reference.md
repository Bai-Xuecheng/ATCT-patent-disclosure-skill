# 《专利交底书模板.docx》字段与写法参考

## 模板整体结构

最终 DOCX 必须按以下顺序填充：

1. 编号
2. 撰写人、手机、邮箱、座机
3. 技术问题联系人、手机、邮箱、座机
4. 发明名称
5. 关键词（3–5 个）：中文、英文
6. 检索式：中文、英文
7. 相关技术检索结果
   - ▇期刊或书籍等现有技术检索.（必填）
   - ▇ 中国专利检索（必填）
8. 相关性分析
9. 摘要、代表性附图
10. 技术领域
11. 背景技术
12. 发明内容
    - 要解决的技术问题和有益的技术效果
    - 所有的实施方式
    - 可替代的技术方案
13. 附图
14. 着重保护的技术创新点

## 写作风格

### 文头和检索区

- 发明名称应完整，避免只有项目名。
- 中文关键词用顿号分隔；英文关键词用英文逗号或顿号均可，但保持统一。
- 检索式用 `AND / OR` 组合，体现同义词扩展。
- 检索结果可以按“方向 + 代表性文献/专利 + 未公开内容”组织。

### 相关性分析

写本发明与现有技术的区别，不能只重复摘要。参考句式：

```text
本发明与现有技术的区别在于，现有技术通常将……作为相对独立的功能模块处理，缺少……。本发明将……放在同一控制链路中处理，使……能够随……联动调整。
具体差异包括：第一，……；第二，……；第三，……；第四，……。
```

### 摘要

摘要为 1 段，通常 250–600 字，包含：

- “本发明公开一种……”开头；
- 技术对象；
- 核心步骤或模块；
- 输出结果；
- 技术效果。

不要在摘要中写“本技能”“本文档”“不构成法律意见”。

### 技术领域

用 1 句或 1 段，格式：

```text
本发明/本申请涉及……技术领域，具体涉及一种……方法/系统/设备/介质。
```

### 背景技术

背景技术应是连续正文，不是清单。推荐 4–8 段：

1. 行业/场景背景；
2. 最近似现有技术；
3. 现有技术实施方式；
4. 现有技术缺陷；
5. 引出本方案必要性。

### 要解决的技术问题和有益效果

建议分两部分：

```text
一、要解决的技术问题
1. ...
2. ...

二、有益的技术效果
1. ...
2. ...
```

技术问题应与背景技术缺陷对应；有益效果应与实施方式中的技术手段对应。

### 所有的实施方式

必须至少两个实施方式。方法类推荐写法：

```text
实施方式一：……方法
如图1和图2所示，本实施方式包括以下步骤。
S1，……。
S2，……。
...

实施方式二：……设备/系统/介质
如图3所示，本实施方式包括……模块，所述模块用于……。
```

轨道交通、控制算法、视频推理等方法类也可用：

```text
步骤一：……
步骤二：……
步骤三：……
```

要求：

- 写明关键输入、处理、判断、输出；
- 写明核心公式、阈值、参数的含义；
- 涉及附图时必须引用“图1、图2”；
- 避免只写“构建模块、进行处理、输出结果”的空泛流程。

### 可替代的技术方案

若确有替代方案，写要点、优点、缺点；没有时写“无”。

### 附图

附图区域统一写：

```text
图1
图2
图3

图1为……图
图2为……图
图3为……图
```

如果已生成图片，应插入高清 PNG 并在图下写说明。注意：图号、图题和“图1为……图”只能出现在 Word 正文图注/附图说明中，不得出现在图片内部。

附图图片本体必须采用以下统一风格：

- 白底、黑色边框、黑色文字、黑色箭头；
- 卡片式矩形模块，少装饰、无彩色填充、无渐变、无阴影；
- 根据内容选择排布：线性流程用纵向，数据流水线用横向，系统架构或并行模块用多层堆叠/分层 rank；
- 图片内部不写图号、图题、说明性标题或“图1为……图”。

为了便于后续修改，附图应同时保留可编辑源文件，优先顺序为：

1. Graphviz `.dot` 源文件，适合流程图、架构图、模块关系图；
2. SVG 矢量图，适合无损缩放和转入其他绘图工具；
3. PNG 高清图，适合插入 Word 模板并保证兼容显示。

若 `drawings` 中只提供 `path`，则只能插入已有图片；若提供 `nodes`/`edges` 或 `dot`，工具会自动生成上述源文件和高清图。`drawings` 可使用 `layout` 指定 `vertical`、`horizontal` 或 `layered`；复杂架构可使用 `ranks`/`layers` 指定同层节点。

### 着重保护的技术创新点

用编号列出 4–8 点。推荐句式：

```text
着重保护的技术创新点
1. 保护“……”的……机制。
2. 保护“……”的……方法。
3. 保护“……”的……闭环。
```

每个保护点必须能在实施方式中找到对应实现。
